## 1. 本書の位置づけ

要求定義書の要求（F-XXX・N-XX）を、実装できる規則に落とし込む。いまあるのは計算の規則（§5）で、候補・連休・持ち分の計算がこの規則どおりに動く。画面の構成・寸法・文言は画面定義書が持つ。

挙動の判断が要るときは、コードより先に本書を直す。この規則にない挙動を実装者が単独で決めない。

## 2. システム方式

### 2.1 全体構成

```
[GitHub Actions: 月 1 回] 内閣府の syukujitsu.csv を取得 → 検証 → src/data/holidays.json
        │ 差分があればコミット → Vercel が自動デプロイ
        ▼
[ビルド: Next.js の全ページ静的生成] 祝日 JSON と domain の純関数で、設定なしの候補を HTML に入れる
        │
        ▼
[ブラウザ] 同じ JSON と同じ関数で計算する。設定・日程は端末の保存領域から読む
```

サーバー・DB・認証は持たない（N-01）。利用者の端末から外部へ祝日を取りに行かない（F-601）。

### 2.2 技術スタック

| レイヤ | 採用 | 選定理由 |
|---|---|---|
| 枠組み | Next.js 16.4.5（App Router）。`output: 'export'` は使わない | 全ページをビルド時に生成でき、アカウントを足すときに API と DB を同じアプリへ足せる（要求定義書 §8） |
| UI | React 19.3.1 + Tailwind CSS 4（`@tailwindcss/postcss`） | hitosuji・bassdrill と共通 |
| 言語 | TypeScript 5 | 同上 |
| テスト | Vitest 5（domain の純関数。モックを使わない） | N-03 |
| 静的検査 | ESLint 10 + eslint-config-next 16.4.5 | `src/domain/**` に、引数なしの `new Date()`、`Date.now()`、クラス宣言を書けない規則を置く |
| 祝日の取り込み | tsx で動かすスクリプト（`holidays:fetch`）と GitHub Actions | F-601、F-602 |
| ホスティング | Vercel の無料枠 | N-06 |

バージョンは hitosuji にそろえる。Node は 22 以上。

### 2.3 コード構成

```
src/domain/   計算の純関数。I/O、引数なしの new Date()、Date.now()、クラスを書かない。型は Readonly。今日の日付は引数で受け取る
src/data/     同梱する祝日データ（holidays.json）
src/app/      Next.js の画面（layout・page）。MVP ではサーバー側の処理（API ルート、Server Actions、cookies() などの動的 API）を書かない
scripts/      祝日の取り込み
```

依存方向は domain ← app。domain は React と Next.js を知らない。日付は `IsoDate`（`'YYYY-MM-DD'` の文字列）で持ち、日本の暦日として扱う（N-07）。端末やビルド機のタイムゾーンで結果が変わらない。

### 2.4 リポジトリ・環境

- 単一リポジトリ `renkyu-planner`。main への push で Vercel に自動デプロイする
- 作業はトピックブランチで行い、main へのマージはオーナーの合図を待つ

## 5. 計算の規則

要求 ID（F-XXX・N-XX）を実現する計算の規則。ID は R-1〜R-19 で、実装計画 1 の表を元にし、計画の各タスクが定めていた決まりと、2026-11-15 のオーナーの決定を書き足している。

| ID | 規則 |
|---|---|
| R-1 | **休みの日** = 土曜・日曜、祝日、会社の休日、1 日分の日程が入った日。半日・時間単位の日程の日は休みの日にしない。重なった日の種類は、会社の休日、祝日、土曜・日曜、日程の順で決める。土曜・日曜、祝日、会社の休日に日程が重なっても、その日は元の種類の休みの日として数える |
| R-2 | **連休** = 休みの日が 3 日以上続いた最長の並び。**長め** = 5 日以上の連休（日程を 1 日も含まない連休も長めに数える）。並びを前後に伸ばす計算は 366 日で打ち切り、366 日を超える並びは 366 日の連休として扱う |
| R-3 | **候補** = 休みの日でない日の集合 D（1〜3 日）で、D を休みの日に加えると D の全部を含む 1 つの並びができ、その長さが `D の日数 + 3` 以上になるもの。並びは前後に伸ばせるだけ伸ばした最長のものを取る |
| R-4 | 候補の D に、今日より前の日と、すでに日程が入っている日（量を問わない）は含めない |
| R-5 | 候補の**核** = 候補の並びが含む、祝日か会社の休日に当たる平日（月〜金）のうち最初の日。同じ核の候補を 1 つの組にまとめる。祝日か会社の休日に当たる平日が並びに無いときは、並びの中の `leave` でない最初の休みの日を核にする |
| R-6 | 候補の**四半期** = D の最初の日が入る四半期。組の四半期は、組の中で最も効率のよい候補の四半期。最も効率のよい候補が同じ効率で複数あれば、休む日数の少ないものを取る。休む日数も同じなら、D の最初の日が早いものを取る |
| R-7 | 並べ方: 四半期の中で、組を「最も効率のよい候補の効率（並びの日数 ÷ D の日数）」の大きい順、同じなら核の早い順。組の中は D の日数の少ない順、同じなら並びの長い順、さらに同じなら D の最初の日の早い順 |
| R-8 | **祝日のない月の候補**（F-205）= 月〜金に祝日も会社の休日もない月。ただし、その月に 1 日分の日程がすでにある月と、月の末日が今日より前の月には出さない。選択肢は、その月の金曜と月曜のうち、今日以降で、休みの日でも日程のある日でもないもの。選択肢が 1 つもない月には出さない |
| R-9 | **未確定** = 候補の並びの最終日の翌日が、祝日の確定期限（`confirmedUntil`）より後である候補。祝日のない月の候補は、月の末日が確定期限より後なら未確定 |
| R-10 | **対象の期間** = 今日が入る四半期の初日から、4 つ目の四半期の末日まで（F-508） |
| R-11 | **量**は分で持つ。1 日 = 所定労働時間（分）、半日 = その半分（0.5 分の端数を許す）。表示は「9 日と 2 時間」「2 時間 30 分」「3 日」「0 日」の形で、分未満は切り捨てる。負の量は絶対値を同じ形にし、呼び出し側が「不足」を付ける |
| R-12 | **付与年** = 付与日（月日）以降で最も近い過去の付与日から、次の付与日の前日まで。付与日に 2 月 29 日は使えない |
| R-13 | **持ち分** = 休暇の種類と付与年ごとに決める。有休は、その付与年に持ち分の上書きがあればその値。無ければ `付与日数 × 所定労働時間 + 繰り越し`。**付与日数** = その付与年に入れた値。無ければ、それより前でいちばん近い付与年の値。それも無ければ 0。**繰り越し** = 設定のあるいちばん古い付与年と、それより前の付与年は 0。それより後の付与年は、直前の付与年の未割り当て（0 未満なら 0）と、直前の付与年の `付与日数 × 所定労働時間` の小さいほう。繰り越しは計算の内訳で、利用者が入れる値ではない。足した休暇の種類は `日数 × 所定労働時間`。取得済み = その付与年の取得済みの日程の量の合計、予定 = 取得済みでない日程の量の合計、残り = 持ち分 − 取得済み、未割り当て = 残り − 予定（負になりうる）（F-101、F-405） |
| R-14 | **四半期の長めの休暇** = 開始日がその四半期に入る、5 日以上の連休。複数あれば最も長いもの、同じ長さなら早いもの |
| R-15 | 会社の休日の「毎年同じ月日」は年をまたいでよい（12-30〜01-03）。開始月日が終了月日より後なら、翌年の終了月日までと読む。会社の休日 1 件の長さは 31 日まで。「その年だけ」は、開始日が終了日より後なら受け付けない。受け付けない会社の休日は入力欄で断り、計算でも無いものとして扱う（保存したデータやファイルの読み込みは入力欄を通らないため） |
| R-16 | 祝日の取り込みは、次のどれかに当たれば失敗として反映しない: 見出しの行が「国民の祝日・休日月日,国民の祝日・休日名称」と一致しない、行が 1 件も読めない、日付の形が違う行がある、同じ日付の行が 2 つ以上ある、既存のデータにある祝日が 1 件でも消えている（今日より前か後かを問わない）、件数が既存の 9 割未満。法改正などで祝日が実際に移った・無くなったときは、人が内容を確かめて手で取り込む（手順は README）。`confirmedUntil` は最後の祝日の年の 12 月 31 日。`updatedAt` は祝日の内容が変わったときだけ今日の日付にする。`checkedAt` は取り込みが成功するたびに今日の日付にし、内容が変わらなくてもコミットする（F-602） |
| R-17 | 日程は、休みの日（土曜・日曜、祝日、会社の休日）の日付には、量を問わず足せない。入力欄で断る。あとから会社の休日や祝日と重なった日程は消さずに残し、重なっていることを出す。利用者が消すまでは持ち分から引く |
| R-18 | **年 5 日の取得**（F-404）= 付与日数が 10 日以上の付与年を対象に、その付与年の有休の日程を、1 日分は 1 日、半日は 0.5 日として数える。時間単位の日程は数えない。取得済みと予定を合わせて 5 日に届いていないあいだ、あと何日かを知らせる。付与年の末日まで 90 日以内は、警告として出す。付与日数は R-13 のとおりに見る |
| R-19 | 日程を足せる日付は、対象の期間（R-10）の末日まで。それより先の日付は受け付けない。今日より前の日付は足せる。すでにある日程を直すときは、この決まりを当てない |

### 5.1 計算の細かい決まり

実装計画 1 で管理側が決め、オーナーが確認した決まり。表の規則を補う。

- 有休は、最初から 1 件入っている休暇の種類。識別子は `paid`、名前は「有休」。画面での表記（有休・有給）は画面定義書で決める
- 候補の列挙は、D の最初の日の早い順、同じなら D の日数の少ない順で返す。画面に出す順は R-7 が決める
- 祝日のない月の候補（R-8）が対象にするのは、計算する期間に 1 日でもかかる月。月の早い順に返す
- R-8 の「1 日分の日程がある月」は、取得済みかどうかと休暇の種類を問わない。選択肢から外す「日程のある日」は、量を問わない
- 設定に無い休暇の種類を指定された持ち分の計算は、持ち分 0 として計算する
- 組を開かずに見せる候補は、組の中で休む日数がいちばん少ないものの全部（R-7 の順なので、連休の長い順に並ぶ）。残りは 1 行にまとめる
- 持ち分の計算（R-13）は、設定のあるいちばん古い付与年から、求める付与年まで順に行う
- 組を 1 件で代表させるときは、R-6 と同じ選び方（効率が最大、同じなら休む日数が少ない、さらに同じなら D の最初の日が早い）の候補を使う
- 実装計画 1 の仮のページは、四半期の見出しを「2026年 10〜12月」、確定期限を「2027年12月31日」の形で出す。主な画面の文言は画面定義書で決める
- 会社の休日の長さ（R-15 の 31 日）は、2 月 29 日がある年で数えた日数とする（02-01〜03-02 は 31 日）
- 連休を伸ばす計算の打ち切り（R-2 の 366 日）は、前へ伸ばしてから後ろへ伸ばし、合計が 366 日に達したところで止める

## 6. 保存するデータ

記録を端末に置く形と、読めないときの扱い。

| ID | 決まり |
|---|---|
| D-1 | 記録は `localStorage` のキー `renkyu-planner` に、1 つの JSON 文字列で置く |
| D-2 | 形は `{ "version": 1, "settings": Settings, "entries": Entry[] }`（N-02）。`Settings` と `Entry` は `src/domain/types.ts` の型 |
| D-3 | 読むときに形を確かめる。JSON として読めない、`version` が 1 でない、必要な項目が無い・型が違う、のどれかなら失敗とする。`version` が 1 より大きい記録（新しい版が書いたもの）も失敗とし、古い画面が上書きしない。新しい版の記録を読んだときは、保存を止める（D-9 と同じ扱い） |
| D-4 | 項目ごとの決まり。日程: `id` は空でない文字列で重複しない、`date` は実在する日付、`amount` は `day`・`half`・`minutes`（1 以上の整数の分）のどれか。設定: `workMinutes` は 1〜1440 の整数、`grantDay` は null か R-12 を満たす月日、`grantYears` のキーは実在する日付で、値は `grantDays`（0 以上の数）と `entitlementMinutes`（持ち分の上書き。null か、0 以上の整数の分）、`leaveTypes` の先頭は `id` が `paid` の有休。会社の休日は形だけを確かめ、R-15 に合わないものも保存はできる（計算が無いものとして扱う）。知らない項目は読み捨てる |
| D-5 | 読むのに失敗したときは、元の文字列をキー `renkyu-planner:unreadable` に写してから、空の記録で始める。画面には「保存されていた記録を読めませんでした」と 1 行出す。写しは 1 件だけ持ち、次に失敗したら上書きする。写しを書けなかったときは、元の記録を上書きしないよう、保存を止める（D-9 と同じ扱い） |
| D-6 | 何も保存されていないときは、空の記録（`DEFAULT_SETTINGS` と日程 0 件）で始める |
| D-7 | 変えるたびに、記録の全体を書き直す。日程の `id` は `crypto.randomUUID()` で作る。`crypto.randomUUID()` が無い環境（https でも localhost でもない接続）では、`crypto.getRandomValues()` で同じ形の文字列を作る |
| D-8 | ほかのタブが同じ記録を書き換えたら（`storage` イベント）、読み直して画面を計算し直す。ページが復元されたとき（`pageshow`）と、見える状態に戻ったときにも読み直す。保存を止めているあいだ（D-9）は読み直さない |
| D-9 | 保存領域が使えないとき（読み書きが例外になる）は、記録をメモリにだけ持ち、画面定義書 §3.11 の 1 行を出す（N-08） |
