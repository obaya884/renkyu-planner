# 要求定義書 決定ログ

- [要求定義書](./11_要求定義書.md)の「なぜそうしたか」を日付順に積む。本文は現在の仕様だけを持つ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-11-14 | スプレッドシート「人生を豊かにするシート」の「有休計画」「祝日一覧」を、ほかの人も使えるサービスにする | オーナーの「より一般的に利用できる機能や構造にしてリリースしたい」 |
| 2026-11-14 | MVP は記録を端末に保存する。アカウント機能と、端末にある記録の引き継ぎは、利用が伸びそうなら検討する | オーナー決定。有休の記録は年に十数行で端末の保存で足り、ログインを挟まないほうが初めての人が試しやすい（Claude の提案）。「記録を持たない」案は残数の管理ができないので採らなかった |
| 2026-11-14 | サービスの強みを有休候補（どこを休むと連休になるか）に置く。使った人に起きることは「連休が上手く作れる」「四半期に 1 度くらい長めの休暇が有休と祝日で作れる」「付与された有休を余らせない」の 3 つ | オーナー指定 |
| 2026-11-14 | 候補は並べて自分で選ぶ形にする。年間の案を自動で組む形は候補に回す | オーナー決定。結婚式や体調不良のように候補と関係なく決まる休みが混ざるので、自分で選ぶ形がシートの使い方に近い（Claude の提案） |
| 2026-11-14 | 長めの休暇は 5 連休以上とする | Claude の案をオーナーが承認 |
| 2026-11-14 | 会社ごとの休みを「会社の休日」（日付が決まっていて全員が休む）と「休暇の種類」（日数が決まっていて日は自分で選ぶ）の 2 つに分けて持つ。慶弔休暇の自動計算と、会社ごとの細かい規則は対象外 | オーナーの「年末年始や夏季休暇、特別休暇など、勤める企業の福利厚生にある程度対応したい」に対する Claude の案。オーナーが「その分け方で収まる」と承認 |
| 2026-11-14 | シートの 2 種類の規則（飛び石埋め、祝日のない月の 3 連休）を個別に持つのをやめ、「休暇を 1〜3 日使うと何連休になるか」を全部計算する。祝日のない月の 3 連休は残す | 会社の休日と休暇の種類を足すと、曜日だけで決める規則では候補を出しきれない。飛び石埋めは計算の結果の 1 つとして出る（Claude の案。オーナーは異論なし） |
| 2026-11-14 | 1 年は有休の付与日から数える。四半期は 1 月始まり（1〜3 月、4〜6 月、7〜9 月、10〜12 月）にする | 年・年度・付与日の 3 案を比べた。「余らせない」は付与日から数えないと確かめられないので付与日にした。四半期は当初、付与日の月から 3 か月ずつとしたが、オーナーが「素直に 1 月始まりで良い」と指定。四半期は長めの休暇があるかを見るためだけに使うので、付与年とずれていても困らない |
| 2026-11-14 | 消化量は小数でなく「1 日」「半日」「何時間」で入れる。1 日の所定労働時間を設定に持つ | オーナー指定。シートの小数は自分で計算してから入力していて手間だった |
| 2026-11-14 | 主な画面は、四半期ごとの一覧を主役にし、小さな月カレンダーを添える（モック A）。年間カレンダーを主役にする案（モック B）は採らない | ブラウザのモックで 2 案を比べ、オーナーが A を選んだ。強みにしたい候補が画面の中心に来る |
| 2026-11-15 | 祝日の出所を内閣府の CSV にし、ビルド時に取り込んで同梱する。Holidays JP API は使わない | オーナーの依頼で Holidays JP の実装と更新の信頼度を調べた。元が Google カレンダーで公式でない、ビルドが年 1 回（2024 年 9 月から）で年の途中の変更が入らない、メンテナが 1 人、2024 年 9 月に祝日でない日が約 1 週間混ざった、という不安があった。作者の対応は速く（issue 2 件を 6 日と 17 日で修正）来年末までの出所としては使えるが、祝日を間違えると候補がすべて狂うので公式にした。同梱にすれば出所が止まっても動き続け、利用者の端末から外部へ通信しない。オーナー決定 |
| 2026-11-15 | 名称を連休プランナー（renkyu-planner）とする。題は「連休プランナー｜有給管理もできる休暇計画サービス」 | オーナーが「SEO や AIO に強そうな名前」を求めた。最初の案「連休メーカー」は同じ名前で内容も近いサービス（darashi/renkyu-maker）があるとオーナーが指摘し、取り下げた。「連休」という探される語が入り、一覧を見るだけでなく計画するものだと分かる名前にした。題はオーナー案。「とびいし」などの和語の案は、検索での見つかりやすさを優先して採らなかった |
| 2026-11-15 | 競合を「連休を見つけるもの」と「有給を記録するもの」の 2 つの型に分け、違いを 4 つ（会社の休みで計算、1 年を通した計画、候補が記録につながる、登録なしでどの端末でも）に定める | オーナーの「他サービスを競合と見立てて、差別化や優位性をハッキリさせておきたい」。6 つのサービスを調べ、両方をつないだものが見つからなかった。オーナーが「見立ては合っている」と承認 |
| 2026-11-15 | カレンダーへの書き出しを MVP に入れる（Google カレンダーに追加するリンクと .ics ファイル）。購読と通知は候補に回す | オーナーは「入れたいが、iCal の書き出しだけになるなら無くてもよい」。Google カレンダーへは予定作成のリンクで直接追加でき、.ics は iPhone の標準カレンダーに追加できるので、Claude が入れる前提で起こした。オーナーの確認待ち |
| 2026-11-15 | 最初に返す HTML に説明文と設定なしの候補を入れる（N-04）。作り方は bassdrill と同じ Vite の SPA から見直す | 検索と AI からの見つかりやすさをオーナーが重視している。SPA は最初の HTML が空で、スクリプトを実行しない読み手には内容が届かない（Claude の判断。手段は未決 U-1） |
| 2026-11-15 | 祝日が確定している範囲（内閣府が公表した来年末まで）と出所を、ページ上で利用者に示す（F-605） | オーナー指定。競合は 2029 年まで出しており、対象の年では負けている。確定した祝日だけを使っていることを隠さずに示す |
| 2026-11-15 | 価値を C-1〜C-5 の順に置く | オーナーが挙げた 3 つの体験と、端末保存・登録なしの決定を価値に写した（Claude の案。オーナーの確認待ち） |
| 2026-11-15 | 草案の点検（別の読み手に「これだけで計画が立てられるか」を読ませた）で出た抜けを埋める。付与年は日付から自動で決め、日程はその日付が入る付与年の持ち分から引く。主な画面は今日が入る四半期から 4 つの四半期を出す。日程に入れた 1 日分の休みは休みの日として候補を計算し直す。半日と時間単位の休みは連休に数えない。所定労働時間は分まで入れられる。最初の HTML に入れる候補は固定の期間にする。F-209 と F-405 を Must に上げる | 設定済みの人に見せる期間、次の付与日より後の日程の数え方、日程と候補の関係、半日の扱いが書かれておらず、Must の F-402 が Should の F-405・F-209 なしでは付与日をまたぐ場面で成り立たなかった。いずれも Claude の判断で、オーナーの確認待ち |
| 2026-11-15 | 枠組みを Next.js にし、Vercel に置いて全ページをビルド時に生成する。`output: 'export'` は使わず、MVP ではサーバー側の処理を書かない（未決だった U-1 を閉じる） | Astro に React を載せる形、Next.js、Vite にプリレンダリングを足す形の 3 案を比べた。Astro は静的サイトとして最も素直で新しい枠組みの学びもあるが、連動する主な画面では軽さの利点が薄い。Next.js は hitosuji で慣れていて、伸びたときのアカウント機能へ同じアプリのまま進める。bassdrill で Next.js を採らなかったのはページが 1 枚でブラウザ内の動きだけだったためで、検索向けの内容とアカウントへの道がある本サービスとは事情が違う。Claude は当初 Astro を推し、比較のあと Next.js に変えた。オーナー決定 |
| 2026-11-15 | F-602 を、差分があるときだけでなく、取り込みが成功するたびに確認した日を記録してデプロイする形に改める | 取り込みが止まっていないことを、毎月のコミットで確かめられるようにする。オーナー決定（経緯は [log_12](./log_12_要件定義書.md)） |
| 2026-11-15 | F-404 を「付与年の終わりが近いのに未割り当てが残っていることを知らせる」から「年 5 日の取得に届いていないことを知らせる」に改め、F-406（使える期間の終わりが近い休暇の知らせ）を削る | 画面のブレストでのオーナーの判断。有休はたいてい 1 年繰り越せて、残りと未割り当てはいつも出ているので、使い切りを明示して促すまでは要らない。知らせたいのは、年 5 日の取得に足りていないこと（労働基準法 39 条 7 項。年 10 日以上付与される人に、会社が 5 日を取らせる義務）。数え方は厚生労働省の Q&A で確かめた（半日は 0.5 日、時間単位は数えない） |
