# 連休プランナー 実装計画 2: 主な画面と日程

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 端末に記録を保存し、主な画面（スマホと PC）で候補を見て日程に入れ、日程を直し、付与日と日数を入れて持ち分を見られるようにする。

**Architecture:** 画面に出す内容は `src/domain/view/` の純関数が「表示用の組み立て」（文言を含まないデータ）として作る。React の部品は、その組み立てと `src/app/texts.ts` の文言を受け取って描くだけにし、`renderToStaticMarkup` で HTML を確かめる。記録は `localStorage` に 1 つの JSON で置き、形の検証は domain、読み書きは `src/app/store/` が持つ。最初の HTML は実装計画 1 の静的な候補の一覧のままで、端末が記録を読んだあとに差し替える。

**Tech Stack:** Next.js 16.4.5（App Router）/ React 19.3.1 / TypeScript 5 / Tailwind CSS 4 / Vitest 5。新しい依存は足さない。

**Spec:** [docs/仕様/13_画面定義書.md](../仕様/13_画面定義書.md)（画面）、[docs/仕様/12_要件定義書.md](../仕様/12_要件定義書.md)（規則 R-1〜R-18）、[docs/仕様/11_要求定義書.md](../仕様/11_要求定義書.md)（要求）

## この計画の範囲

画面定義書の全部を 1 つの計画にすると長くなりすぎるので、2 つに分ける。本書だけで、設定なしの人が候補を日程に入れ、付与日を入れて残りを見る、という使い方が通る。

| 2（本書） | 保存するデータ、年 5 日の取得、主な画面（S-1）、面 M-1・M-2・M-3、過ぎた四半期 | F-101、F-106、F-107、F-201〜F-207、F-209〜F-211、F-301〜F-306、F-401〜F-405、F-501〜F-503、F-507、F-508、N-02、N-03、N-04、N-07、N-08 |

## 保存するデータの決まり（要件定義書 12 §6 に写す。Claude の案で、この計画の承認をもってオーナー確認とする）

| ID | 決まり |
|---|---|
| D-1 | 記録は `localStorage` のキー `renkyu-planner` に、1 つの JSON 文字列で置く |
| D-2 | 形は `{ "version": 1, "settings": Settings, "entries": Entry[] }`（N-02）。`Settings` と `Entry` は `src/domain/types.ts` の型 |
| D-3 | 読むときに形を確かめる。JSON として読めない、`version` が 1 でない、必要な項目が無い・型が違う、のどれかなら失敗とする。`version` が 1 より大きい記録（新しい版が書いたもの）も失敗とし、古い画面が上書きしない |
| D-4 | 項目ごとの決まり。日程: `id` は空でない文字列で重複しない、`date` は実在する日付、`amount` は `day`・`half`・`minutes`（1 以上の整数の分）のどれか。設定: `workMinutes` は 1〜1440 の整数、`grantDay` は null か R-12 を満たす月日、`grantYears` のキーは実在する日付で、値は `grantDays`（0 以上の数）と `entitlementMinutes`（持ち分の上書き。null か、0 以上の整数の分）、`leaveTypes` の先頭は `id` が `paid` の有休。会社の休日は形だけを確かめ、R-15 に合わないものも保存はできる（計算が無いものとして扱う）。知らない項目は読み捨てる |
| D-5 | 読むのに失敗したときは、元の文字列をキー `renkyu-planner:unreadable` に写してから、空の記録で始める。画面には「保存されていた記録を読めませんでした」と 1 行出す。写しは 1 件だけ持ち、次に失敗したら上書きする |
| D-6 | 何も保存されていないときは、空の記録（`DEFAULT_SETTINGS` と日程 0 件）で始める |
| D-7 | 変えるたびに、記録の全体を書き直す。日程の `id` は `crypto.randomUUID()` で作る。`crypto.randomUUID()` が無い環境（https でも localhost でもない接続）では、`crypto.getRandomValues()` で同じ形の文字列を作る |
| D-8 | ほかのタブが同じ記録を書き換えたら（`storage` イベント）、読み直して画面を計算し直す |
| D-9 | 保存領域が使えないとき（読み書きが例外になる）は、記録をメモリにだけ持ち、画面定義書 §3.11 の 1 行を出す（N-08） |

import { expect, test } from 'vitest'
import { DEFAULT_SETTINGS } from '@/domain/types'
import { fiveDayStatus } from './fiveDays'

const e = (date: string, amount: object, done: boolean, leaveTypeId = 'paid') => ({ id: date, date, leaveTypeId, amount, title: '', done }) as never
const D = { unit: 'day' }, H = { unit: 'half' }, M = { unit: 'minutes', minutes: 120 }
const settings = { ...DEFAULT_SETTINGS, grantDay: '05-01', grantYears: { '2026-05-01': { grantDays: 14, carryOverMinutes: 0 } } }
const base = { settings, grantYearStart: '2026-05-01', today: '2026-11-15' }

test('R-18: 1 日分は 1 日、半日は 0.5 日。時間単位は数えない', () => {
  const s = fiveDayStatus({ ...base, entries: [e('2026-05-15', D, true), e('2026-06-01', H, true), e('2026-06-02', M, true), e('2026-12-28', D, false)] })
  expect(s).toEqual({ doneDays: 1.5, plannedDays: 1, remainingDays: 2.5, warn: false })
})
test('R-18: 予定を含めて 5 日に届けば残りは 0', () => {
  const entries = ['2026-06-01', '2026-06-02', '2026-06-03'].map((d) => e(d, D, true)).concat(['2026-12-28', '2026-12-29'].map((d) => e(d, D, false)))
  expect(fiveDayStatus({ ...base, entries })?.remainingDays).toBe(0)
})
test('R-18: 付与年の末日まで 90 日以内で届いていなければ警告', () => {
  expect(fiveDayStatus({ ...base, today: '2027-01-29', entries: [] })?.warn).toBe(false) // 末日 4/30 まで 91 日
  expect(fiveDayStatus({ ...base, today: '2027-01-30', entries: [] })?.warn).toBe(true)  // 90 日
  expect(fiveDayStatus({ ...base, today: '2027-04-30', entries: [] })?.warn).toBe(true)
})
test('R-18: 付与日数が 10 未満・付与日が未設定・ほかの休暇の種類・別の付与年', () => {
  const few = { ...settings, grantYears: { '2026-05-01': { grantDays: 9, carryOverMinutes: 0 } } }
  expect(fiveDayStatus({ ...base, settings: few, entries: [] })).toBeNull()
  expect(fiveDayStatus({ ...base, settings: DEFAULT_SETTINGS, entries: [] })).toBeNull()
  const s = fiveDayStatus({ ...base, entries: [e('2026-08-12', D, true, 'summer'), e('2027-05-06', D, false)] })

import { describe, expect, test } from 'vitest'
import { DEFAULT_SETTINGS } from '@/domain/types'
import { EMPTY_STORED, parseStored, serializeStored } from './stored'

const entry = { id: 'a', date: '2026-11-20', leaveTypeId: 'paid', amount: { unit: 'day' }, title: '', done: false }
const ok = { version: 1, settings: DEFAULT_SETTINGS, entries: [entry] }
const parse = (o: unknown) => parseStored(JSON.stringify(o))

describe('保存するデータ（N-02、D-2〜D-4）', () => {
  test('書き出して読むと元に戻る', () => {
    expect(parseStored(serializeStored(EMPTY_STORED))).toEqual({ ok: true, value: EMPTY_STORED })
    expect(parse(ok)).toEqual({ ok: true, value: ok })
  })
  test('知らない項目は読み捨てる', () => {
    const r = parse({ ...ok, extra: 1, entries: [{ ...entry, memo: 'x' }] })
    expect(r).toEqual({ ok: true, value: ok })
  })
  test('Review Focus 1: JSON でない・形が違う・新しい版は失敗', () => {
    expect(parseStored('').ok).toBe(false)
    expect(parseStored('{oops').ok).toBe(false)

    expect(parse({ ...ok, version: 2 }).ok).toBe(false)
    expect(parse({ ...ok, version: '1' }).ok).toBe(false)
    expect(parse({ version: 1, entries: [] }).ok).toBe(false)
  })
  test('D-4: 日程の決まり', () => {
    const bad = (patch: object) => parse({ ...ok, entries: [{ ...entry, ...patch }] }).ok
    expect(bad({ date: '2027-02-29' })).toBe(false)
    expect(bad({ id: '' })).toBe(false)
    expect(bad({ amount: { unit: 'minutes', minutes: 0 } })).toBe(false)
    expect(bad({ amount: { unit: 'minutes', minutes: 1.5 } })).toBe(false)

    expect(bad({ done: 'yes' })).toBe(false)
    expect(parse({ ...ok, entries: [entry, entry] }).ok).toBe(false) // id の重複

    expect(bad({ leaveTypes: [] })).toBe(false)
    expect(bad({ leaveTypes: [{ id: 'summer', name: '夏季休暇', days: 3, usable: null }] })).toBe(false)
    expect(bad({ grantYears: { '2026-05-01': { grantDays: -1, carryOverMinutes: 0 } } })).toBe(false)
    expect(bad({ companyHolidays: [{ kind: 'yearly', start: '01-01', end: '12-31' }] })).toBe(true)
    expect(bad({ companyHolidays: [{ kind: 'monthly' }] })).toBe(false)

### Task 4: 四半期の節の組み立て

**Files:**
- Create: `src/domain/view/quarterView.ts`
- Test: `src/domain/view/quarterView.test.ts`

**Interfaces:**
- Consumes: `PlannerInput`、`restCalendarOf`、`currentGrantYear`（Task 3）、`findCandidates`、`groupCandidates`、`monthGaps`、`runContaining`、`longBreakOf`、`balanceOf`、`grantDaysOf`、`Quarter`
- Produces:
  - `type DayMark = 'done' | 'planned' | 'candidate' | 'company' | 'off'`（重なったときはこの順で前を優先。画面定義書 §3.6）
  - `type DayCell = Readonly<{ date: IsoDate; day: number; mark: DayMark | null; grantDay: boolean }>`
  - `type MonthView = Readonly<{ month: IsoDate; weeks: readonly (readonly (DayCell | null)[])[] }>`（日曜始まり。1 週は 7 つで、その月でない所は null）
  - `type CandidateRow = Readonly<{ leaveDays: readonly IsoDate[]; run: Run; long: boolean; unconfirmed: boolean; nextGrantYear: boolean; shortMinutes: number | null }>`（`nextGrantYear` は、今日が入る付与年の次の付与年の日を 1 日でも含むとき。`shortMinutes` は、入れると未割り当てが負になる付与年があるとき、その不足の分（正の数。複数の付与年で不足するなら合計）。付与日が未設定なら null）
  - `type CandidateBlock = Readonly<{ kind: 'group'; core: IsoDate; primary: readonly CandidateRow[]; rest: readonly CandidateRow[]; restHasLong: boolean } | { kind: 'monthGap'; month: IsoDate; unconfirmed: boolean; rows: readonly CandidateRow[] }>`（`primary` は組の中で効率が最大のもの全部。`rest` は残りを R-7 の順で。`monthGap` の `rows` は選択肢を 1 日ずつ、日付の早い順）
  - `type EntryRow = Readonly<{ entry: Entry; overdue: boolean; overlap: boolean; run: Run | null }>`（`overdue` は予定で日付が今日より前。`overlap` は、その日が土日・祝日・会社の休日。`run` は、1 日分の日程がその日を含む 3 日以上の連休に入るとき）
  - `type EntryBlock = Readonly<{ run: Run | null; rows: readonly EntryRow[] }>`（同じ連休に入る日程が 2 件以上なら、その連休を `run` に持つ 1 つの塊。それ以外は `run` が null で 1 件ずつの塊。塊は、先頭の日程の日付の早い順）
  - `type GrantNote = Readonly<{ date: IsoDate; entered: boolean; grantDays: number }>`（その四半期に、今日より後に来る付与日があるとき。`entered` は、その付与年の `grantYears` があるか。`grantDays` は `grantDaysOf`）
  - `type QuarterView = Readonly<{ quarter: Quarter; past: boolean; longBreak: Run | null; months: readonly MonthView[]; marks: readonly DayMark[]; grantNote: GrantNote | null; candidates: readonly CandidateBlock[]; entries: readonly EntryBlock[] }>`（`past` は末日が今日より前。`past` のとき `candidates` は空で、`candidate` の印も付けない。`marks` は、その四半期の月カレンダーに出ている種類を `DayMark` の順で）
  - `buildQuarterViews(input: PlannerInput, quarters: readonly Quarter[]): QuarterView[]`

候補は過ぎていない四半期の最初の日から最後の日までを 1 回で列挙して組にまとめ（R-10）、組の `quarterStart` が一致する四半期に置く。祝日のない月の候補は、その月が入る四半期の、組の後ろに置く。月カレンダーの `candidate` の印は、`primary` の休む日にだけ付ける。

**Interfaces:**
- Consumes: `previewAdd`、`checkEntryDraft`、`checkGrantDraft`、`EntryDraft`、`GrantDraft`（Task 5）、`plannerStore` の操作（Task 6）、`runContaining`、`restCalendarOf`
- Produces:
  - `Sheet(props: { title: string; onClose: () => void; children: React.ReactNode }): JSX`（§5 の共通の決まり。標準の `<dialog>` を `showModal()` で開く。スマホは下から、PC は中央。面の外を押すと閉じる。Esc で閉じるのは `<dialog>` の標準の動き）
  - `AddSheet(props: { input: PlannerInput; leaveDays: readonly IsoDate[]; onSubmit: (drafts: readonly EntryDraft[]) => void; onClose: () => void }): JSX`（§5.1。`previewAdd` の結果を、付与年の数だけ行にして出す。付与日が未設定なら、その行の代わりに `T.enterGrantToSee` を出す。「予定に入れる」で、休む日ごとに 1 日分の予定の下書きを作って `onSubmit` に渡す）
  - `EntrySheet(props: { input: PlannerInput; entry: Entry | null; defaultDate: IsoDate; onSubmit: (draft: EntryDraft) => void; onRemove: () => void; onClose: () => void }): JSX`（§5.2。`entry` が null なら「日を足す」。`checkEntryDraft` のエラーがあるあいだは保存できない。`overOneDay` は知らせだけ。「この日程を消す」は 1 回押すとすぐ `onRemove` を呼ぶ。「Google カレンダーに追加」は計画 3）
  - `GrantSheet(props: { input: PlannerInput; grantYearStart: IsoDate | null; onSubmit: (draft: GrantDraft, grantYearStart: IsoDate) => void; onClose: () => void }): JSX`（§5.3。`grantYearStart` が null なら初めての入力で、付与日の欄を出し、入れた付与日と今日から付与年を決める。null でなければ、付与日は文字で出し、その付与年の日数と繰り越しを入れる。次の付与年の繰り越しの初期値は、今の付与年の未割り当て（0 未満なら 0）。保存先の 1 行 `T.localOnly` を出す）

`Planner` は開いている面を 1 つだけ状態に持つ（`{ kind: 'add'; leaveDays } | { kind: 'entry'; id: string | null } | { kind: 'grant'; grantYearStart: IsoDate | null } | null`）。Task 7・8 で何もしない関数を渡していた所を、面を開く動きに替える。`onSubmit` と `onRemove` は、ストアの操作を呼んでから面を閉じる。「日を足す」の日付の初期値は、開いている四半期の中の、今日以降で最も早い平日（土日・祝日・会社の休日でない日）。過ぎた四半期では、その四半期の最後の平日。
