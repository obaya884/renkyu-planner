# 連休プランナー 実装計画: まとめて取る休暇の候補

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 「まとめて取る休暇」の印がある休暇の種類（例: フリーバカンス。5 日、1 月 1 日に付与、営業日で連続して 1 回で取る）について、その日数ぶんを営業日で続けて休む取り方を候補に出す（F-212、R-20）。候補はふつうの候補の上に種類ごとの組で出し、「日程に入れる」で開くモーダル（M-1）では、その種類を引く休暇の初期値にする。あわせて、日を足すモーダル（M-2）に「終わりの日」を足し、期間の営業日ぶんの日程をまとめて足せるようにする（F-307）。

**Architecture:** 候補の列挙は `src/domain/candidates/togetherCandidates.ts` の純関数 1 つに置く。休みの日のカレンダー（`buildRestCalendar`）と、設定・日程・今日・R-19 の末日を引数で受け、R-20 の条件、四半期ごとの並べ方、5 件の上限までをこの関数で済ませる。表示用の組み立ては `src/domain/view/togetherBlocks.ts` に置き、`buildQuarterViews` が四半期ごとの `together` として返す。部品 `TogetherList` はその組み立てと `texts.ts` の文言を描くだけにする。モーダルは `AddSheet` に引く休暇の初期値を外から渡す props を足し、`Planner` がまとめて取る休暇の候補から開いたときだけ渡す。`defaultLeaveTypeId` は変えない（ふつうの候補では、まとめて取る休暇を初期値にしないまま）。期間でまとめて足す日の列挙と検証は `src/domain/entries/entryRange.ts`、モーダルに出す形は `src/domain/view/rangePreview.ts` に置き、保存は既存の `addEntries`（複数の日程を 1 回で足す）を使う。

**Tech Stack:** Next.js 16.4.5（App Router）/ React 19.3.1 / TypeScript 5 / Tailwind CSS 4 / Vitest 5。新しい依存は足さない。

**Spec:** [docs/仕様/12_要件定義書.md](../仕様/12_要件定義書.md)（R-1〜R-3、R-9、R-13、R-17、R-19、R-20）、[docs/仕様/13_画面定義書.md](../仕様/13_画面定義書.md)（§3.6、§3.7、§5.1、§5.2）、[docs/仕様/11_要求定義書.md](../仕様/11_要求定義書.md)（F-104、F-212、F-306、F-307）

## Review Focus

1. **R-20 の条件が全部効いていること。** 付与年をまたぐ D、日程のある日を含む D、1 日分の日程の日をまたぐ D、その種類の日程がある付与年、使える期間の外、日数が整数でない種類、有休の付与日が無いとき、のそれぞれで出ないこと。次の付与年の分は付与される前から出ること（Task 1）
2. **並べ方と上限。** 四半期ごとに並びの長い順、同じなら D の最初の日の早い順で、5 件で切ること（Task 1）
3. **ふつうの候補と月カレンダーが変わらないこと。** まとめて取る休暇の種類を足しても、ふつうの候補の組、引く休暇の初期値、月カレンダーの印が、足す前と同じであること（Task 2）
4. **モーダルの初期値の経路。** まとめて取る休暇の候補から開いたときだけ、その種類が初めから選ばれていること。ふつうの候補から同じ日を開いても有休のままであること（Task 3）
5. **期間でまとめて足す。** 土日・祝日・会社の休日を飛ばし、1 日分の日程がある日には足すこと。4 つの理由で保存できないこと。直すときは終わりの日の欄が出ないこと（Task 4）
6. **入れたあとの計算し直し。** 候補を日程に入れると、その付与年の組だけが消え、次の付与年の組は入れた日を休みの日として数え直した連休で残ること。期間で足した日程が持ち分と日程の欄に入ること（Task 5）

### Task 1: まとめて取る休暇の候補の列挙（R-20）

**Files:**
- Create: `src/domain/candidates/togetherCandidates.ts`
- Modify: `src/domain/candidates/findCandidates.ts`（`withLeaveDays` を export するだけ）
- Test: `src/domain/candidates/togetherCandidates.test.ts`

**Interfaces:**
- Consumes: `RestCalendar`、`Run`、`runContaining`（`restDays.ts`）、`withLeaveDays`（`findCandidates.ts`）、`grantYearOfType`（`balance.ts`）、`quarterStart`、`addDays`（`shared/date.ts`）、`Settings`・`Entry`（`types.ts`）
- Produces:
  - `type TogetherCandidate = Readonly<{ leaveDays: readonly IsoDate[]; run: Run }>`（`leaveDays` は D を日付の早い順に）
  - `type TogetherQuarter = Readonly<{ quarterStart: IsoDate; candidates: readonly TogetherCandidate[] }>`
  - `const TOGETHER_LIMIT = 5`（R-20 の上限）
  - `findTogetherCandidates(input: Readonly<{ cal: RestCalendar; settings: Settings; entries: readonly Entry[]; leaveTypeId: string; today: IsoDate; end: IsoDate }>): TogetherQuarter[]`
    - `cal` は `restCalendarOf(input)` のカレンダー。`end` は R-19 の末日（呼び出し側は `lastAddableDate(today)` を渡す）
    - 種類が見つからない、`together` が false、`days` が 1 以上の整数でない、有休の付与日が無い（`grantYearOfType` が null）、のどれかなら `[]`
    - 営業日は、`cal.kindOf(d)` が `'weekend'`・`'holiday'`・`'company'` のどれでもない日（`null` と `'leave'`）。1 日分の日程の日（`'leave'`）は営業日として数え、飛ばさない（R-20）。`cal.isRest` で判定しない（`'leave'` を休みの日に数えてしまう）
    - D の作り方: `today` から `end` までの営業日 d0 から、土日・祝日・会社の休日だけを飛ばして営業日を N 日取る。N 日目が `end` より後なら、その d0 は捨てる
    - D を捨てる条件（R-20）: D のどれかの日に日程がある（量と種類を問わない。1 日分の日程の日もここで捨てる）。D の最初の日と最後の日で `grantYearOfType` の開始日が違う。その付与年にその種類の日程が 1 件でもある（取得済みかどうかと量を問わない）。使える期間があり、D のどれかの日の月日が期間の外（`defaultLeaveTypeId` と同じ、月日の文字列での比較）。`withLeaveDays(cal, D)` で `runContaining(…, D[0])` が null（3 日未満）
    - 連休は `withLeaveDays(cal, D)` のカレンダーで求める。前後の 1 日分の日程の日は `'leave'` で休みの日なので、並びに入る（R-20）
    - 返す形: 四半期の初日の早い順。候補が 1 件も無い四半期は入れない。四半期の中は `run.days` の大きい順、同じなら `leaveDays[0]` の早い順で、先頭から `TOGETHER_LIMIT` 件
  - 列挙は 1 日ずつ d0 を進める素直な形でよい（期間は 1 年弱、N は 366 まで）

  - `type RangeError = 'invalidDate' | 'endBeforeStart' | 'tooFar' | 'noDays' | 'tooManyDays'`
  - `const MAX_RANGE_DAYS = 31`
  - `rangeDays(input: PlannerInput, start: IsoDate, end: IsoDate): Readonly<{ days: readonly IsoDate[]; errors: readonly RangeError[] }>`（`entryRange.ts`。§5.2）
    - 足す日は `start` から `end` までで、`restCalendarOf(input).kindOf(d)` が `'weekend'`・`'holiday'`・`'company'` のどれでもない日。1 日分の日程がある日（`'leave'`）も足す日に入れる（§5.2「すでに日程がある日にも足す」）。`start` が休みの日でも断らず、飛ばす（H-1 の推奨）
    - 理由はこの順に調べ、当たったものを全部返す。`start` か `end` が実在する日付でない → `invalidDate`（ほかは調べない）。`end < start` → `endBeforeStart`。`end > lastAddableDate(input.today)` → `tooFar`（R-19）。`endBeforeStart` も `tooFar` も無いときだけ数える。足す日が 0 → `noDays`。足す日が `MAX_RANGE_DAYS` を超える → `tooManyDays`
    - 32 日目の足す日が見つかったら数えるのをやめる（`start` が遠い過去でも固まらない）。理由があるときの `days` は `[]`
  - `type RangePreview = Readonly<{ days: readonly IsoDate[]; errors: readonly RangeError[]; overOneDay: boolean; run: Run | null; deltas: readonly GrantYearDelta[] }>`
  - `previewRange(input: PlannerInput, start: IsoDate, end: IsoDate, leaveTypeId: string): RangePreview`（`rangePreview.ts`）
    - `days`・`errors` は `rangeDays` のまま。`days` が空なら `overOneDay: false`・`run: null`・`deltas: []`
    - `overOneDay` は、足す日のどれかで `checkEntryDraft(input, { date, leaveTypeId, amount: { unit: 'day' }, title: '', done: false }, null).overOneDay`（F-306）
    - `run` は、足す日の全部を 1 日分の日程として足したカレンダーで `runContaining(…, days[0])`（§5.2「全部を足したあとの形」）
    - `deltas` は `previewAdd(input, days, leaveTypeId)`（H-2 の推奨。状態が取得済みでも、未割り当ては同じ量だけ減るので `previewAdd` のままでよい）
  - `rangeDaysText(days: readonly IsoDate[]): string`（`texts.ts`。`'12/28(月)・12/29(火)・1/4(月) の 3日ぶんを足します'`）
  - `EntryRangeLines({ preview, workMinutes }: { preview: RangePreview; workMinutes: number }): JSX`（`EntrySheet.tsx` から export する、表示だけの部品。終わりの日の欄の下に、`errors` があれば `errorText` の理由を 1 つ 1 行（`role="alert"`、`tooFar` には `lastAddableDate` を渡す）、無ければ `rangeDaysText(days)` の 1 行。`overOneDay` なら `T.overOneDay`。`deltas` があれば M-1 と同じ未割り当ての行（1 行なら `T.unassigned`、2 行なら `delta.current` で `T.thisGrantYear`・`T.nextGrantYearLabel`。負は警告の色）。`run` があれば `runHeading(run)` の連休の行）

  - `EntrySheetBody`・`EntrySheet` の `onSubmit` を `(drafts: readonly EntryDraft[]) => void` にする。1 件のときは `[draft]`、期間のときは足す日ごとの `{ date, leaveTypeId, amount: { unit: 'day' }, title, done }`
  - `Planner`: M-2 の `onSubmit` は、直すときは `plannerStore.updateEntry(openedEntry.id, drafts[0])`、足すときは `plannerStore.addEntries(drafts)`（既存。1 回の保存で全部が入る）
  - 直すときは終わりの日の欄を出さない（§5.2「足すときだけ出す」）
