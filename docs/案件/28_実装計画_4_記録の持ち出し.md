# 連休プランナー 実装計画 4: 記録の持ち出し

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 端末のブラウザにだけある記録を、端末の外へ持ち出せるようにする。記録と設定をファイルに書き出し、そのファイルを読み込んで、いまの記録を置き換えられる。読み込んだ直後なら、読み込む前の記録に戻せる（F-505）。これからの予定を、.ics ファイルにまとめて書き出せ、日程のモーダルから「Google カレンダーに追加」を開ける（F-506）。設定画面に「記録の持ち出し」の節を足し、「記録をすべて消す」も置く（13 §6）。記録とファイルの検証を 1 つにそろえ、件数・文字の長さ・id の文字に上限を置く。

**Architecture:** 記録の検証は `parseStored`（`src/domain/storage/stored.ts`）の 1 つだけにし、localStorage の記録と読み込むファイルの両方に使う。上限の数は `src/domain/storage/limits.ts` に置き、検証と入力欄の両方がそこを見る。ファイルの大きさはファイルを読む前に app の側で見る。.ics と Google カレンダーの URL の形は、文字列を受け取って文字列を返す純関数として `src/domain/transfer/` に置き、予定の題（文言）は `src/app/texts.ts` が作る。ブラウザでファイルを扱う処理（`Blob`、`<a download>`、`File.text()`）は `src/app/transfer/download.ts` に閉じ込める。読み込みはストアの `replaceAll`、記録をすべて消すのはストアの `clearAll` で行い、どちらも保存を止めているあいだの決まり（D-3・D-5・D-9）を守る。置き換える前の記録は、設定画面の部品の状態（メモリ）に 1 回ぶんだけ持つ。記録を外へ送る通信は無い。外のサービスに渡るのは、利用者が「Google カレンダーに追加」を押して開いた URL の、その 1 件の日付と題だけ（N-05）。

**Tech Stack:** Next.js 16.4.5（App Router）/ React 19.3.1 / TypeScript 5 / Tailwind CSS 4 / Vitest 5。新しい依存は足さない（.ics は RFC 5545 の終日の予定だけを書けばよく、文字列の組み立てで足りる）。

**Spec:** [docs/仕様/11_要求定義書.md](../仕様/11_要求定義書.md)（F-505、F-506、N-01、N-02、N-05、N-07、N-08）、[docs/仕様/12_要件定義書.md](../仕様/12_要件定義書.md)（§6 の D-1〜D-9、R-15、R-17、R-19）、[docs/仕様/13_画面定義書.md](../仕様/13_画面定義書.md)（§2、§5、§5.2 の「カレンダー」の行、§6 の「記録の持ち出し」の行とその下の箇条書き、§8.3）。経緯は [log_11](../仕様/log_11_要求定義書.md)・[log_12](../仕様/log_12_要件定義書.md)・[log_13](../仕様/log_13_画面定義書.md) の最後の行（2026-11-15）

## 日程が指す休暇の種類（計画で決めた推奨。オーナーに確かめる）

設定に無い種類を指す日程がある記録とファイルは、**読めない扱いにする**（12 D-4 に足す。Task 1）。いまのコードを読んで、そのまま読んだときに画面で困ることを確かめた。

- 日程の行の 2 行目に種類の名前が出ない（`quarterView.ts:121` は、見つからない種類の名前を null にする）。有休の日程と同じ見た目になるのに、有休の持ち分からは引かれない（持ち分のカードは `leaveTypes` の種類ごとに作るので、どのカードにも数えられない）
- 日程のモーダル（M-2）を開くと、`<select>` の値がどの選択肢にも合わないので、ブラウザは先頭の「有休」を選んだ見た目で出す（推測。React の制御された `<select>` のふつうの動き）。`checkEntryDraft` は `unknownLeaveType`（「引く休暇を選んでください」）を出して保存させない。見た目の「有休」を選び直しても `onChange` が起きないので、ほかの種類を選んでから戻さないと保存できない。種類が有休だけの記録では選ぶ欄が出ない（`EntrySheet.tsx` の `leaveTypes.length >= 2` の分岐）ので、消すしかない
- 画面からはこの記録を作れない。`removeLeaveType` は日程が残っている種類を消さず（`createPlannerStore.ts:136`）、種類の `id` は変えられない。localStorage の記録で読めない扱いにしても、手で書き換えない限りこれまでの記録は読める

## Review Focus

1. **悪意のあるファイルを渡される。**
   - 巨大な入力で固まらない: 1MB を超えるファイルは中を読まない。1MB 以内でも、件数と文字の長さの上限で、計算に渡る量が決まる（Task 1、Task 3）
   - スクリプトが動かない: 名前の中の `<script>` などは、React の描画で文字のまま出る。`dangerouslySetInnerHTML` が無いことを `grep` で確かめる（Task 7）
   - .ics とリンクへの細工: 名前の改行・`;`・`,`・`\`・`END:VEVENT`・`BEGIN:VALARM` で、書き出した .ics の行の構造が変わらない。id は英数字・ハイフン・下線だけなので、UID から行を足せない。Google カレンダーのリンクは、題に `&`・`#`・改行を入れても、行き先のホストとパラメータの区切りが変わらない（Task 1、Task 5、Task 6）
   - 読み込みで記録を失わない: 確かめるモーダルの件数で、別のファイルに気づける。読み込んだ直後なら戻せる（Task 3）
2. **読めないファイルでは何も変わらない。** 決まりに 1 つでも合わないファイルは、確かめるモーダルを開かず、記録が少しも変わらないこと（Task 1、Task 3）
3. **アプリが書いた記録が、次に読めなくなることが無い。** 入力欄と、ストアの追加の操作が上限を守ること。上限いっぱいの記録が `parseStored` で読めること（Task 1、Task 2）
4. **確かめずに置き換わらない。読み込む前に戻すのは直後だけ。** 「やめる」・モーダルの外・Esc のどれでも記録が変わらないこと。ファイルの選択から戻ったときの読み直し（D-8 の `visibilitychange`）で、開いているモーダルが消えないこと。読み込んだあとにほかの変更をすると「読み込む前に戻す」が消えること（Task 3）
5. **保存を止めているとき。** 新しい版の記録が localStorage にあるとき、読み込んでも localStorage の記録が書き換わらないこと。「記録をすべて消す」では消えて、保存できる状態に戻ること（Task 3、Task 4）
6. **外へ送るもの。** 書き出しと読み込みで通信が起きないこと。Google カレンダーへ渡るのは、押したときの 1 件の日付と題だけであること（Task 6、Task 7）
7. **スマホ。** iOS の Safari と Android の Chrome で、書き出したファイルが保存でき、そのファイルを読み込めること（Task 7 の実機）

## 確かめた期待値と、確かめていない所

期待値は計画を書くときに、いまのコード（`parseStored`、`isNewerVersion`、`amountText`、fixture の `SHEET`）と node を呼んで数えた。

- Task 1: 上限ちょうどの記録（日程 5,000 件、会社の休日 100 件、休暇の種類 100 件、付与年 200 件（1826〜2025 年の 5 月 1 日）、名前 100 文字、64 文字の id）は、いまの `parseStored` で読める。1 つ超えた記録、`nowhere` を指す日程、M-5 で作れない休暇の種類、`1.5` の版は、いまは読めてしまう（実装前に FAIL する）。境目のテストは、いまのコードで通る
- `isNewerVersion('{"version":1.5}')` はいま true。`grantYears` の `__proto__` のキーは、いま「grantYears のキーが合いません」で読めない
- `SHEET` を読むと、日程 12 件、会社の休日 1 件、休暇の種類 1 件（有休だけ）

- `amountText({ unit: 'minutes', minutes: 120 }, 480)` は `2 時間`。半日は `4 時間` と出るので、題では `T.amountHalf` の「半日」を使う

- `renderToStaticMarkup` は `href` の `&` を `&amp;` にする
- .ics の折り返しの位置は `TextEncoder` で数えた（1 行目 74 オクテット、2 行目 25 オクテット）
