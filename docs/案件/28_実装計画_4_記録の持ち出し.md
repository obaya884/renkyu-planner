# 連休プランナー 実装計画 4: 記録の持ち出し

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **下書き。** 下の「仕様に答えが無い点」は、まだオーナーの答えをもらっていない。各タスクの手順は、その表の「推奨」で書いてある。答えが推奨と違ったら、仕様に書いたあとで、その点に当たる手順と期待値を直してから実行する。

**Goal:** 端末のブラウザにだけある記録を、端末の外へ持ち出せるようにする。記録と設定をファイルに書き出し、そのファイルを読み込んで、いまの記録を置き換えられる（F-505）。日程をカレンダーに追加できる。設定画面から .ics ファイルをまとめて書き出し、日程のモーダルから「Google カレンダーに追加」を開く（F-506）。設定画面に「記録の持ち出し」の節を足す（13 §6）。

**Architecture:** ファイルの中身を作る処理と読む処理は、文字列を受け取って文字列か結果を返す純関数として `src/domain/transfer/` に置く。ブラウザでファイルを扱う処理（`Blob`、`<a download>`、`File.text()`）は `src/app/transfer/` の小さな関数に閉じ込め、domain はファイルを知らない。読み込みは `parseStored` の項目ごとの読み方を共有し、項目ごとに落とした件数を返す `parseImportFile` を新しく置く。localStorage を読む `parseStored`（D-3）の扱いは変えない。読み込んだ記録はストアの `replaceAll` で全体を置き換え、ほかの変更と同じく保存を止めているあいだ（D-3・D-5・D-9）は書かない。.ics と Google カレンダーの URL の形は domain が作り、予定の題（文言）は `src/app/texts.ts` が作る。記録を外へ送る通信は無い。外のサービスに渡るのは、利用者が「Google カレンダーに追加」を押して開いた URL だけ（N-05）。

**Tech Stack:** Next.js 16.4.5（App Router）/ React 19.3.1 / TypeScript 5 / Tailwind CSS 4 / Vitest 5。新しい依存は足さない（.ics は RFC 5545 の終日の予定だけを書けばよく、文字列の組み立てで足りる）。

**Spec:** [docs/仕様/11_要求定義書.md](../仕様/11_要求定義書.md)（F-505、F-506、N-01、N-02、N-05、N-07、N-08）、[docs/仕様/12_要件定義書.md](../仕様/12_要件定義書.md)（§6 の D-1〜D-9、R-15、R-17、R-19）、[docs/仕様/13_画面定義書.md](../仕様/13_画面定義書.md)（§2、§5、§5.2 の「カレンダー」の行、§6 の「記録の持ち出し」の行とその下の箇条書き、§8.3 の「読み込んだファイルが読めない」）。経緯は [log_12](../仕様/log_12_要件定義書.md) の 2026-11-15 の 2 行（会社の休日を黙って落とす、読み込みで落とした件数を知らせる）と [log_11](../仕様/log_11_要求定義書.md) の 2026-11-15（カレンダーへの書き出しを MVP に入れる）

## Global Constraints

- バージョン: `next` 16.4.5、`react`・`react-dom` 19.3.1、`tailwindcss` ^4、`vitest` ^5、`typescript` ^5、`eslint` ^10。Node は 22 以上。**依存を足さない**
- **Next.js のコードを書く前に `node_modules/next/dist/docs/` の該当ガイドを読む**（この計画では `01-app/03-api-reference/01-directives/use-client.md`。ページは足さないので、ルートの設定は触らない）
- `src/domain/` は純関数だけ。I/O、引数なしの `new Date()`、`Date.now()`、クラスを書かない。型は `Readonly`。今日の日付と、.ics の `DTSTAMP` に使う今の時刻は、必ず引数で受け取る。React と Next.js を import しない。`Blob`・`File`・`URL.createObjectURL`・`document` も domain に書かない
- 日付は `IsoDate`（`'YYYY-MM-DD'`）で持ち、日本の暦日として扱う（N-07）。.ics の終日の予定は `VALUE=DATE` で書き、タイムゾーンを付けない
- サーバー側の処理（API ルート、Server Actions、動的 API）を書かない（N-01）。記録を送る通信を書かない（N-05）。`/` と `/settings` は静的なまま（ビルドの出力で `○ /` と `○ /settings`）
- **画面に出す文言と、予定の題に使う文言は、すべて `src/app/texts.ts` に置く**。部品と domain に日本語の文字列を直接書かない。文言は仮で、計画 5（V-1）でまとめて直す。画面定義書に文があるものは、その文のとおりに書く
- 部品（`src/app/components/`）は表示だけを持つ。計算や判定をせず、props で受けた組み立てと文言を描く。ファイルを選ぶ `<input type="file">` は部品に置いてよいが、選んだ `File` を props の関数に渡すだけにする
- テストはコロケーション。モックを使わない。保存領域のテストはメモリ上の小さな実装を使う（`createPlannerStore.test.ts` の `memory()`）。部品は `renderToStaticMarkup` で確かめ、モーダルは中身の部品（`…Body`）を直接描く。テスト名は日本語で、要求 ID か規則 ID（D-10 などの新しい ID を含む）を入れる。`Blob` と `<a download>` を使う関数（`src/app/transfer/download.ts`）は node のテストで確かめられないので、ブラウザで確かめる
- テストは日本以外のタイムゾーン（`vitest.config.mts` の `TZ`）で流れる。`DTSTAMP` は UTC の文字列から作り、ローカルの時刻を使わない
- 色と寸法は画面定義書 §7 の仮の値。スマホで本文 14px 以上、押せる要素の高さ 44px 以上
- コミットは `type(scope): 要約`、末尾に `Co-Authored-By: Claude <モデル名> <noreply@anthropic.com>`
- シェルは zsh。`npm` は `command npm`、`npx` は `command npx` と書く
- 作業はブランチ `feat/transfer`（`main` から切る）で行う。`main` へのマージはオーナーの合図を待つ
