# 連休プランナー 実装計画 3: 設定

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 設定の面（S-2）を作り、付与日と付与年ごとの日数、所定労働時間、週の始まり、会社の休日、休暇の種類を、主な画面を使い始めたあとでも直せるようにする。新しい付与年の知らせと、使える期間のある休暇を先に充てる候補も足す。

**Architecture:** 設定の面は別の経路 `/settings` に置く。ページは静的に生成し、中身は端末で動く部品 `SettingsScreen` が描く。記録は主な画面と同じストア（`plannerStore`）を読み書きするので、主な画面に戻ると計算し直した結果が出る。行に出す内容は `src/domain/view/settingsView.ts` の純関数が組み立て、部品はその組み立てと `texts.ts` の文言を描くだけにする。入力の検証は `src/domain/entries/` に置く。

**Tech Stack:** Next.js 16.4.5（App Router）/ React 19.3.1 / TypeScript 5 / Tailwind CSS 4 / Vitest 5。新しい依存は足さない。

**Spec:** [docs/仕様/13_画面定義書.md](../仕様/13_画面定義書.md)（§3.1、§3.2、§3.10、§5、§5.3〜§5.5、§6、§8.3）、[docs/仕様/12_要件定義書.md](../仕様/12_要件定義書.md)（R-12、R-13、R-15、R-17、§6 の D-1〜D-9）、[docs/仕様/11_要求定義書.md](../仕様/11_要求定義書.md)（F-101〜F-108、F-208、F-405、F-407、F-504、F-605）

## Review Focus

1. **主な画面と設定の面を行き来する。** 設定の面で変えた内容が、主な画面に戻ると計算し直されて出ること。設定の面を直接開いても記録を読むこと。保存できないブラウザでメモリにある記録が、行き来で消えないこと（Task 1、Task 9）
2. **会社の休日を足して、すでにある日程と重なる。** 日程は消えず、主な画面で「休みの日と重なっています」が出て、持ち分から引かれたままになること（R-17。Task 5）
3. **所定労働時間を奇数の分（7 時間 45 分）にする。** 持ち分、候補の行、面に「0 日足りません」「不足 0 日」が出ないこと（`isShort` の 1 か所の判定。Task 2）
4. **日程が残っている休暇の種類と、有休。** 消せず、理由が出ること。保存した記録が `parseStored` で読めること（Task 6）
5. **使える期間のある休暇。** 候補の行の不足と、M-1 の初期値と未割り当ての行が、同じ休暇の種類で数えられていること（Task 7）
