# 連休プランナー 実装計画 1: 土台と計算

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Next.js の土台、内閣府の祝日の取り込み、候補・連休・持ち分の計算（テストつき）を作り、設定なしの候補が最初の HTML に入った最小のページをビルドできるようにする。

**進め方:** サブエージェント方式（superpowers:subagent-driven-development）。2026-11-15 にオーナーが計画を承認し、この方式を選んだ。

## 計算の規則（要件定義書 12 に写す。Claude の案で、この計画の承認をもってオーナー確認とする）

| ID | 規則 |
|---|---|
| R-1 | **休みの日** = 土曜・日曜、祝日、会社の休日、1 日分の日程が入った日。半日・時間単位の日程の日は休みの日にしない |
| R-2 | **連休** = 休みの日が 3 日以上続いた最長の並び。**長め** = 5 日以上の連休（日程を 1 日も含まない連休も長めに数える） |
| R-3 | **候補** = 休みの日でない日の集合 D（1〜3 日）で、D を休みの日に加えると D の全部を含む 1 つの並びができ、その長さが `D の日数 + 3` 以上になるもの。並びは前後に伸ばせるだけ伸ばした最長のものを取る |
| R-4 | 候補の D に、今日より前の日と、すでに日程が入っている日（量を問わない）は含めない |
| R-5 | 候補の**核** = 候補の並びが含む、祝日か会社の休日に当たる平日（月〜金）のうち最初の日。同じ核の候補を 1 つの組にまとめる |
| R-6 | 候補の**四半期** = D の最初の日が入る四半期。組の四半期は、組の中で最も効率のよい候補の四半期 |
| R-7 | 並べ方: 四半期の中で、組を「最も効率のよい候補の効率（並びの日数 ÷ D の日数）」の大きい順、同じなら核の早い順。組の中は D の日数の少ない順、同じなら並びの長い順、さらに同じなら D の最初の日の早い順 |
| R-8 | **祝日のない月の候補**（F-205）= 月〜金に祝日も会社の休日もない月。ただし、その月に 1 日分の日程がすでにある月と、月の末日が今日より前の月には出さない |
| R-9 | **未確定** = 候補の並びの最終日の翌日が、祝日の確定期限（`confirmedUntil`）より後である候補。祝日のない月の候補は、月の末日が確定期限より後なら未確定 |
| R-10 | **対象の期間** = 今日が入る四半期の初日から、4 つ目の四半期の末日まで（F-508） |
| R-11 | **量**は分で持つ。1 日 = 所定労働時間（分）、半日 = その半分（0.5 分の端数を許す）。表示は「9 日と 2 時間」「2 時間 30 分」「3 日」「0 日」の形で、分未満は切り捨てる。負の量は絶対値を同じ形にし、呼び出し側が「不足」を付ける |
| R-12 | **付与年** = 付与日（月日）以降で最も近い過去の付与日から、次の付与日の前日まで。付与日に 2 月 29 日は使えない |
| R-13 | **持ち分** = 休暇の種類と付与年ごとに、`付与日数 × 所定労働時間 + 繰り越し（分）`。足した休暇の種類は `日数 × 所定労働時間`。取得済み = その付与年の取得済みの日程の量の合計、予定 = 取得済みでない日程の量の合計、残り = 持ち分 − 取得済み、未割り当て = 残り − 予定（負になりうる） |
| R-14 | **四半期の長めの休暇** = 開始日がその四半期に入る、5 日以上の連休。複数あれば最も長いもの、同じ長さなら早いもの |
| R-15 | 会社の休日の「毎年同じ月日」は年をまたいでよい（12-30〜01-03）。開始月日が終了月日より後なら、翌年の終了月日までと読む |
| R-16 | 祝日の取り込みは、次のどれかに当たれば失敗として反映しない: 行が 1 件も読めない、日付の形が違う行がある、今日より前の日付の祝日が既存のデータから 1 件でも消えている、件数が既存の 9 割未満。`confirmedUntil` は最後の祝日の年の 12 月 31 日。`updatedAt` は祝日の内容が変わったときだけ今日の日付にする |

import { addDays, diffDays, eachDay, isValidIsoDate, monthEnd, quarterEnd, quarterStart, todayInJapan, weekday } from './date'

describe('日付の道具（N-07）', () => {
  test('月末と年末をまたいで加算できる', () => {
    expect(addDays('2026-12-31', 1)).toBe('2027-01-01')
    expect(addDays('2027-03-01', -1)).toBe('2027-02-28')
    expect(addDays('2028-02-28', 1)).toBe('2028-02-29')

  test('曜日は 0 が日曜', () => {

    expect(isValidIsoDate('2027-2-9')).toBe(false)
    expect(isValidIsoDate('2028-02-29')).toBe(true)

  test('Review Focus 1: 今日は端末のタイムゾーンによらず日本の暦日', () => {
    expect(todayInJapan(new Date('2026-12-31T14:59:59Z'))).toBe('2026-12-31')

- [ ] **Step 3: `findCandidates` を実装する**

列挙の方法は、関数の型とテストだけでは決まらないので示す。

```
start〜end の各日 d0 について、d0 が「休みの日でなく、今日以降で、日程のない日」なら
  D = [d0] から始め、次を再帰で 3 日まで試す:
    並び = D を休みに加えたときの、d0 を含む最長の並び
    D の全部がその並びに入り、並びの日数 >= D の日数 + 3 なら候補に加える
    D が 3 日未満なら、並びの終わりの翌日以降で、並びにつながりうる日
    （並びの最終日の翌日）を D に足して続ける
同じ D は 1 回だけ返す（D の最初の日が d0 のものだけを数えればよい）
```

並びの最終日の翌日が休む日にできない日（今日より前、日程がある）なら、そこで止める。`core` は並びの中の「月〜金で、種類が holiday か company の日」の最初。無ければ並びの中の `leave` でない最初の休みの日。
